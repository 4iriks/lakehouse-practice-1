# Результаты эксперимента

Данные получены скриптами из `scripts` на локальном стенде. Время — секунды, размеры в JSON — байты. В таблицах отчёта МБ равен 1 000 000 байт.

| Файлы | Содержание |
|---|---|
| `writes.json` | 12 полных записей Bronze: по три для каждой конфигурации; отдельные времена и query ID трёх таблиц |
| `queries_trino.json` | 48 выполнений Q18; время до получения результата и статистика Trino |
| `queries_spark_*.json` | 48 выполнений Q18 в 12 новых приложениях Spark |
| `summary.json` | Медианы, минимум и максимум измерений, рассчитанные генератором отчёта |
| `bronze_inventory.json` | Размеры, число файлов, реальные физические кодеки и футеры после третьей записи |
| `source_counts.json`, `bronze_checksums.json`, `quality.json` | Проверки количества строк, контрольных сумм, типов, пропусков, ключей и связей |
| `reference_q18.json`, `gold_q18.json`, `gold_q18.csv` | Эталон Q18 и совпавшая с ним Gold-витрина |
| `medallion_inventory.json` | Размеры Silver и Gold |
| `smallfiles_inventory.json`, `metadata_queries.json` | Контрольный опыт с целевым размером файла 1 МиБ и 24 измерения запросов |
| `evolution.json` | Проверки изменения схемы, чтения предыдущего снапшота и восстановления |
| `spark_bronze.json` | Фактические схемы, количества и примеры строк Bronze из Spark |
| `final_inventory.json`, `storage_audit.json` | Итоговый учёт действующих таблиц, старых файлов и остальных объектов бакета |
| `hardware_*.json`, `docker_environment.json`, `images.json`, `services*.txt` | Характеристики машины, версии и подтверждение запущенного стенда; отдельный снимок получен во время работы Spark |

`state=first` и `run=0` — первый запрос в новой JVM движка. `state=repeat` и `run=1..3` — повторы в том же процессе. Кэш ОС и MinIO не очищался. Для каждой конфигурации итоговая медиана первого запуска рассчитана по трём значениям, повторного — по девяти.

`correct=true` записывается только после сравнения всех строк Q18 с эталоном; порядок строк с одинаковыми ключами сортировки не учитывается. Денежные значения и количества сопоставляются после округления до шести знаков. Полная загрузка дополнительно сверяется по независимым от порядка контрольным суммам всех сохранённых колонок.

В `query_stats` сохранены поля статистики Trino без длинных списков операторов. Внешнее `elapsed_s` — отдельное клиентское измерение; оно не обязано совпадать с серверным `elapsedTime`.

Эталон `reference_q18.json` использован для проверки правильности. Его служебное время выполнения не включено в сравнение производительности; для него используются только файлы `queries_*`.
