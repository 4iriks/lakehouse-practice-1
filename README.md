# Практическая работа №1: Lakehouse и бенчмарк форматов

**Горбачёв Вадим Александрович, БИВТ-24-сп-1**

**Вариант 3 — TPC-H Q18, масштаб `sf1`**

[Отчёт по форме преподавателя](отчет.md)

Работа реализует загрузку трёх таблиц TPC-H в Iceberg, преобразование Bronze → Silver → Gold и сравнение Parquet/GZIP, Parquet/ZSTD, ORC/SNAPPY и ORC/ZSTD. Q18 выбирает заказы, в которых суммарное количество товара превышает 300, и возвращает до 100 строк по стоимости заказа.

## Стек

MinIO хранит файлы, Lakekeeper предоставляет Iceberg REST Catalog, PostgreSQL хранит служебные данные каталога. Trino генерирует TPC-H, материализует таблицы и выполняет SQL. Spark читает те же таблицы через тот же каталог и независимо проверяет результат Q18.

Используются PostgreSQL 16.10, Lakekeeper 0.9.5, Trino 476, Spark 3.5.6 и Iceberg 1.9.2 для Spark. MinIO собирается из официального релиза `RELEASE.2025-09-07T16-13-09Z`; архив проверяется по SHA256. Конфигурация находится в [docker-compose.yml](docker-compose.yml).

## Воспроизведение в Windows

Нужны работающий Docker Desktop с Linux-контейнерами и Python 3.12. На использованном стенде Docker доступно около 8 ГиБ памяти. Trino и Spark выполняют бенчмарк последовательно; каждый ограничен четырьмя CPU и 4 ГиБ памяти контейнера.

Из PowerShell в корне репозитория:

```powershell
.\run.ps1 -Stage All
```

Эта команда скачивает зависимости и исходники MinIO, собирает образ, запускает сервисы, создаёт warehouse, загружает данные и проводит измерения. Первый запуск требует времени на загрузку образов и сборку.

Этапы можно запускать отдельно:

```powershell
.\run.ps1 -Stage Setup
.\run.ps1 -Stage Load
.\run.ps1 -Stage Trino
.\run.ps1 -Stage Metadata
.\run.ps1 -Stage Evolution
.\run.ps1 -Stage Spark
.\run.ps1 -Stage Report
```

`Load` пересоздаёт только таблицы этой практической. `Evolution` изменяет демонстрационную копию Silver. Перезапуск бенчмарков заменяет соответствующие JSON-файлы в `results`.

`Report` сверяет контрольные суммы всех колонок Bronze с источником, сохраняет состояние сервисов и заново формирует отчёт из измерений. Этот этап выполняется последним и включён в `All`.

Проверка и остановка:

```powershell
docker compose ps
docker compose exec trino trino --execute "SELECT * FROM lake.gold.q18 ORDER BY totalprice DESC, orderdate"
docker compose stop
```

Остановка сохраняет данные в Docker-томах. SQL Trino доступен на `http://localhost:8080`, Lakekeeper — на `http://localhost:8181`, MinIO — на `http://localhost:9000`. Порты привязаны к localhost. Учебные пароли в Compose предназначены только для этого локального стенда.

## Данные и методика

- Источник — детерминированный генератор `tpch.sf1` в Trino. В Bronze сохранены все строки трёх необходимых таблиц, но только используемые колонки; `linenumber` дополнительно сохраняется для проверки составного ключа позиции.
- Основной Bronze физически находится в `lake.bronze_parquet_zstd`. Представления `lake.bronze.*` дают ему короткие имена без копирования данных.
- Silver проверяет качество исходных данных, агрегирует количество по заказу, нормализует денежный тип и обогащает заказ сведениями о клиенте. Gold материализует Q18.
- Измеряется выполнение исходного Q18 над Bronze, а не чтение маленькой готовой витрины Gold.
- Для записи выполняются три повтора. Время включает генерацию TPC-H, запись данных и commit Iceberg, но не `DROP TABLE` и создание схемы.
- Для каждого движка и конфигурации выполняются три серии. Каждая содержит первый запрос в новом процессе движка и три повторных запроса. Время начинается перед отправкой SQL и заканчивается после получения всех строк результата. Запуск JVM и контейнера в него не входит.
- Кэш ОС и MinIO не очищается. Разница первого и повторных запусков включает прогрев JVM, оптимизатора и метаданных; она не является чистой оценкой одного вида кэша. `CACHE TABLE` в Spark не используется.
- Размер файлов измеряется в байтах. В отчёте МБ = 1 000 000 байт, размер целевого файла в МиБ = 1 048 576 байт. Внешние метаданные Iceberg показаны отдельно от файлов данных; футеры уже входят в размер файлов данных и повторно к нему не прибавляются.
- Результаты ограничены выбранной проекцией `sf1`, одним компьютером и указанными настройками. Это учебный эксперимент, а не сертифицированный результат TPC-H.
